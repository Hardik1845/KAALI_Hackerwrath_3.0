# Kaali Safety

Kaali is a full-stack, mobile-first personal safety companion. The UI is built with plain HTML/CSS/JavaScript, the app server uses Node's built-in HTTP and SQLite modules, and the configured FastAPI service handles SOS dispatch.

## Run it

Install Node.js 22.5 or newer and start Kaali. Start the FastAPI SOS, DeepDefend and Hash Shield services separately when using those features:

```powershell
npm start
```

Open [http://localhost:4173](http://localhost:4173). Run the FastAPI SOS service at `http://127.0.0.1:8001`. For local deepfake image analysis, install `deepfake_engine/requirements.txt` and run `npm run deepfake` on port 8000. For Hash Shield, create `HashShield/.env` from `HashShield/.env.example`, add a SerpApi key (or configure Google Cloud Vision), set the same `API_KEY` in the root `.env` as `HASH_SHIELD_API_KEY`, then run the microservice from the HashShield folder:

```powershell
cd HashShield
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

The browser reaches the full Hash Shield API only through the same-origin Node proxy; its API key stays on the server. The protection screen supports reverse-image web search, hash-only scan, fingerprint vault and matching, candidate-based takedown cases, RDAP host lookup, notice and PDF drafts, self-reported notice dispatch with the 24-hour SLA, status checks, resolution/escalation and overdue case inspection. Web search uses configured providers; it does not scan a user-selected website. Images are sent to the configured external reverse-image provider only after consent. Intimate images skip external search and images involving minors are blocked. Marking a notice sent is always a user action. The first launch creates `.data/saheli.sqlite`; that folder is ignored by Git. Browser camera and location access are available on `localhost` after you grant permission. Run route-model checks with `npm test`.

To relay SOS through the FastAPI endpoint, set `SOS_SERVICE_API_KEY` in `.env` to the service key (never put it in frontend code). The Node server sends `X-API-Key` internally and posts the documented `user_id`, `user_name`, `location`, `trigger_type`, `contacts`, and `passphrase` schema to `POST /api/v1/sos/trigger`. Twilio credentials belong in the FastAPI service's environment. Keep both services bound to localhost for personal use.

Deepfake UI requests use the same-origin Node routes `GET /api/deepfake/health` and `POST /api/deepfake`; Node relays uploads to the local FastAPI routes `GET /health` and `POST /api/v1/detect/deepfake`. These image-analysis APIs are local and unauthenticated, intended for loopback use. They do not call an external model API.

The FastAPI service is responsible for Twilio credential handling and delivery status. The Kaali browser never receives the API key or Twilio credentials.

## What works

- **Safety-aware route comparison:** address search uses OpenStreetMap Nominatim; routes and alternatives come from Valhalla using the selected travel mode: walking, bicycle, car, motorcycle, scooter/moped, or multimodal public transit. Transit requires GTFS schedule data at the routing service. Kaali checks unverified reports from the previous 12 hours within about 160 m of route geometry and samples up to 18 evenly spaced locations per route for OpenStreetMap road tags. The deterministic relative concern score is `50 × min(1, recency/category-weighted concern exposure per km ÷ 4) + 20 × observed-unlit-share + 30 × detour-percent ÷ 30`. Category weights are harassment/following 1.0, unsafe path 0.85, poor lighting 0.7, and other 0.55; each decays linearly to zero over the 12-hour query window. Reports are deduplicated by stored report ID and treated as unverified. Routes at most 30% longer than the shortest valid candidate are eligible. A recommendation appears only when report data is available and every eligible route has route-specific evidence (mapped lighting tags or a relevant report); otherwise assessment is insufficient. Concern reports are assigned once to the nearest of up to six route sections for map highlighting. This score is a comparison aid, not a probability or safety rating. Infrastructure coverage is the share of sampled locations with a mapped road within 65 m. Qualitative evidence confidence is separate from coverage and is not statistically validated. Missing tags do not mean infrastructure is absent or lights are not working. When journey guidance is active, GPS updates can request a reroute using the chosen mode; community notes are checked every 45 seconds.
- **Live map and nearby services:** map tiles and road data come from OpenStreetMap. The nearby support layer queries real OpenStreetMap listings for police stations, hospitals, fire stations, pharmacies and mapped shelters. These listings do not confirm opening hours or availability.
- **SOS and emergency calls:** contacts stay in browser storage. The SOS prompt shows what will be shared and waits for your tap. It can open a phone's SMS composer with an optional Google Maps link, or send through Twilio when configured. A separate call action opens the phone's dialer.
- **Check-in timer:** stores its deadline on this browser and offers an SOS shortcut if it expires. It does not send alerts on its own. Keep Kaali open; the browser may pause timers in the background.
- **Camera burst:** camera access is off until you enable it. While armed, pressing SOS captures five front-camera frames into this browser's IndexedDB. They are never uploaded by Kaali; you can download or delete them in **Evidence & check-in**. The browser must have camera permission and remain open.
- **Deepfake signal:** a local FastAPI service analyzes uploaded images with the bundled MesoNet-4 checkpoint, DCT frequency heuristics and JPEG ELA. The browser sends the image through the local Node server to `127.0.0.1:8000`; processing is in memory and files are not saved. No external model API is used. This engine is CPU-only; processing time depends on the machine and image, and its uncalibrated scores are not proof that an image is authentic or manipulated.
- **Hash Shield:** search the wider web by consenting to send a reference image to configured SerpApi Google Lens / Google Cloud Vision reverse-image discovery. Hash Shield computes SHA-256/pHash/dHash, can compare against a per-browser fingerprint vault, verifies discovered candidates, supports evidence recovery cases, RDAP lookup, takedown drafts/PDF, user-started 24-hour SLA tracking, status probes and escalation guidance. It does not silently dispatch notices. Web results are provider-dependent and are not proof of infringement. Hash Shield stores case/vault/scan metadata in memory by default (lost on restart) or MongoDB if configured; it never saves uploaded image bytes.

## Real-data and service limits

The site does not seed fabricated routes, reports or service locations. It includes an optional practice mode where a person can add clearly marked synthetic reports to see how harassment and other concerns change route explanations; clear practice reports when finished. Its third-party data comes from public OpenStreetMap services and the public Valhalla demo. These community services are best effort, have usage limits, and do not provide a service-level guarantee. Nominatim is queried only after an explicit place search and the app spaces requests to at least 1.1 seconds. For production traffic, switch to service providers or self-hosted instances that you operate.

Safety-route comparisons are based on **recent, anonymous, unverified reports submitted to this Kaali server** and sparse OpenStreetMap tags. Harassment, following and unsafe-path reports are shown as serious concerns; poor-lighting and other notes are shown as cautions. This is an explanation aid, not a crime statistic or official safety rating. A lack of reports means only that none are in this database; missing street-light tags do not mean a street is dark. Mapped facilities, reports, routes and GPS may be incomplete or out of date. A route comparison cannot promise a safe journey. Real reports older than 30 days are removed when the server starts; practice reports remain until cleared in the map's practice controls.

## Privacy and deployment

The default server is single-user and binds only to `127.0.0.1`. There is no account system, administrator console or authentication middleware. Do not expose this prototype directly to the public internet. If you deploy it for other people, first add identity and access control, rate limits and moderation for reports, secure backups, consent and retention policies, abuse protection for SOS/Twilio, HTTPS, and a plan for local emergency contacts in each jurisdiction. Camera and geolocation require a secure context on other devices, typically HTTPS.

Depending on what you use, data sent off this device includes place searches (Nominatim), exact route endpoints (Valhalla), sampled route points for map lighting/sidewalk tags (Overpass), a nearby-support map area (Overpass), and requested map tiles. An SOS includes a phone number and message only when you choose direct Twilio delivery; device messaging shares it with your phone's messaging service after you tap send. Deepfake-check images are sent only to the local DeepDefend service on this computer and processed in memory; they are not saved or sent to an external model API. Camera photos and contacts stay in the browser. For Hash Shield fingerprinting, the reference image is sent to the local service and processed in memory. Wider-web search sends it to the configured external provider only after consent; Hash Shield retains fingerprint metadata and case records in memory by default, or MongoDB if configured.

Map tiles are loaded from `tile.openstreetmap.org` with visible attribution. Review the [OpenStreetMap tile usage policy](https://operations.osmfoundation.org/policies/tiles/) before deployment. Nominatim's [usage policy](https://operations.osmfoundation.org/policies/nominatim/) also applies. Routing and alternatives follow [Valhalla's API](https://valhalla.github.io/valhalla/api/). Deepfake analysis uses a local FastAPI API and bundled PyTorch/OpenCV/SciPy/Pillow dependencies; it does not call a hosted model API.
